# Plan — UI Revamp Against the Design System

**Status:** built — all nine phases complete. Every colour, radius and duration
now resolves through `css/themes.css`; no emoji remain in `js/` or `index.html`;
progress is recorded for questions and for theory chapters.
**Date:** 2026-08-18
**Scope:** a visual and interaction pass over the whole app, driven by
`docs/design/DroidDeck-Design-System.html` v1.0 — new tokens, no emoji, progress
made first-class, one priority signal instead of two, and a light theme that is a
peer rather than an inversion. No change to routing, information architecture or
corpus content.

The design system is a specification, not code to copy: it is a single static
reference page whose values have to be read off and re-implemented in this
codebase's own conventions. It arrives as a bundled React page with its content
gzipped into a `__bundler/manifest` block, so §3 below is the token map extracted
from the real markup rather than a reading of the rendered screenshots.

Nine phases, twenty-eight units of work, thirteen files. The order is the one the
handoff asks for — tokens, app bar, sidebar, question row, filter bar, theory
cards, states — with two prerequisites pulled to the front, because several later
changes cannot land without them.

---

## 1. Why

DroidDeck works. Fourteen topics, 465 questions, 50 theory modules across eight
tracks, two themes, a search that spans both corpora. What it does not do is
*look* like one thing, and it does not answer the question a study tool is asked
most often.

**The visual language is an accumulation, not a system.** Colour arrived per
feature: `--error-color` and `--warning-color` exist alongside `--importance-must`
and `--importance-should` that hold nearly the same values for a different
meaning. Radii run 8/12/16/24 with no rule about which applies where. Emoji do
the work of icons in three files, which means the sidebar renders differently on
every OS and cannot be tinted, printed or shrunk to a favicon.

**Every question looks equally unvisited.** Theory has read-tracking; the
question bank — the thing actually revised the night before an interview — has
none. There is no checkbox, no count, no bar. A reader returning after two days
has no way to find where they stopped, which is the single most common thing they
want to know.

**Two controls say the same thing.** A question card carries a 3px coloured left
edge *and* a coloured tier label. Both encode importance; neither adds to the
other; together they make a list of 135 questions read as a warning log.

**Light theme is a computed inversion.** It reuses dark-theme reds and ambers that
vibrate on white, keeps accent 500 where 500 fails contrast against `#FFFFFF` at
13px, and leaves the constellation canvas at `opacity: .6` — behind body text, on
a light ground.

The design system answers all four, and it is worth applying as a system rather
than as a list of tweaks: the token layer is what makes the rest cheap, and doing
it first is what stops this becoming another accumulation.

Seven facts the phases lean on, each of them checked rather than assumed:

- **465 questions across 14 topics**, five of them grouped into subsections
  (`android` 135, `java` 48, `jetpack-compose` 33, `other-topics` 17,
  `data-structures-algorithms` 10); the other nine are flat.
- **Question ids are not globally unique.** `tools/validate-questions.js` asserts
  exactly one known cross-topic collision and fails on a second. Any progress
  store must therefore key on `topicId + ':' + questionId`, never on the id alone.
- **Key-topic counts are the wall the design system describes.** Worst cases:
  `kotlin` 37 chips, `kotlin-coroutines` 20, `android-tools-technologies` 19,
  `jetpack-compose` 17, `kotlin-flow-api` 17.
- **Theory read state is per *module*, not per chapter.**
  `droiddeck:theory:read` holds a flat array of module ids (`js/theory.js:51`).
  The design system asks module cards to read "3 of 5 chapters", which this store
  cannot express. See §6, F1.
- **All 50 theory modules carry `relatedQuestions`**, so an *Open in Theory*
  action can be built from a reverse index with no corpus edit.
- **The highlighter returns HTML whose spans can cross newlines.**
  `js/code-highlight.js` matches block comments and raw strings in one
  alternation, deliberately. Line numbers must not be produced by splitting that
  HTML on `\n`.
- **Tier filtering is CSS, not a re-render** — `#topicContainer.tier-filtered`
  plus `show-*` classes (`css/components.css:376–396`). Expanded rows survive
  filtering, and that behaviour must survive this pass.

### 3.6 Space, shape, motion

- **Spacing**, 4pt scale: 4 · 8 · 12 · 16 · 24 · 32 · 48. Row rhythm is 12 inside
  a card, 16 between cards, 48 between page blocks.
- **Radius**: 6 inputs and code · 10 rows · 14 cards · full chips. This replaces
  today's 8/12/16/24.
- **Motion**: 120ms ease-out for hover and focus ring; 200ms
  `cubic-bezier(.2,.7,.3,1)` for accordion and tab slide; **0ms** for the theme
  switch — no cross-fade, no flash.
- **Touch**: hit targets ≥ 40px.

## 4. Strategy — two token layers, then delete one

The naïve version of Phase 1 is a find-and-replace of every colour in five CSS
files at once. That is a 2,400-line diff with no way to review it and no way to
bisect a regression. This plan takes a different route.

`css/themes.css` is rewritten as **two layers**. A primitive layer holds the
design system verbatim — `--ds-canvas`, `--accent-500`, `--tier-must-bg`,
`--space-3`, `--radius-row`. An alias layer then redefines every existing token in
terms of it:

```css
/* primitives — the design system, verbatim */
[data-theme="dark"] {
  --ds-canvas:#0A0910; --ds-surface:#12101A; --ds-raised:#1A1726;
  --ds-border:#272235; --ds-text:#F4F2F8; --ds-muted:#A19BB4; --ds-faint:#6E6885;
  --accent-500:#8B5CF6; --accent-600:#7C3AED; --accent-300:#C4B5FD;
}

/* aliases — every name the current CSS already uses, remapped.
   Deleted one at a time as each component group is rewritten. */
[data-theme="dark"] {
  --bg-primary:   var(--ds-canvas);
  --bg-secondary: var(--ds-surface);
  --text-primary: var(--ds-text);
  --accent-color: var(--accent-500);
  --importance-must: var(--tier-must-dot);
}
```

Three things follow. The app is **correctly re-skinned after one commit**, before
any component markup changes — so the palette can be judged on the real app in
both themes rather than on a spec page. Nothing is silently missed, because a
hard-coded hex that survives the sweep is visibly wrong next to re-skinned
neighbours. And each later phase deletes the aliases its component group used, so
the alias block shrinking to nothing is the completion signal for the whole
revamp.

Phase 8 has exactly one job: assert the alias block is empty and no literal hex
outside `themes.css` remains. If either check fails, the revamp is not done.

## 5. Phases

Each phase is independently shippable and leaves the app working. Commits go
straight to `main` with hand-set dates, per `CLAUDE.md`.

**Phase 0 — foundations.** Two things must exist before the components can be
rebuilt, and neither is visible on its own, which is exactly why they come first.
Swap the Google Fonts link from Inter to IBM Plex Sans plus Space Grotesk, and
retriple `--font-*`. Then add `js/progress.js`, modelled on the read-state wrapper
already in `js/theory.js:51–72` — same localStorage-throws tolerance, same
"progress is a convenience, losing it is not worth an error" posture. Three sets:
questions done, questions flagged for review, chapters read. Question keys are
`topicId:questionId`, because ids collide across topics by design. It loads after
`js/theme.js` and before `js/navigation.js`, and `docs/ARCHITECTURE.md`'s
load-order block is updated in the same commit, since that block *is* the
dependency graph. *No visual change.*

**Phase 1 — tokens.** `css/themes.css` rewritten as §4 describes: surfaces,
accent ramp, both tier palettes, category hues, the 4pt scale, the four radii, the
three motion tokens, and an alias for every existing name. Then motion retimed —
`--transition-fast` 150 → 120ms ease-out, `--transition-base` 250 → 200ms
`cubic-bezier(.2,.7,.3,1)`, and `--transition-slow` deleted rather than retimed
because the system has no third duration. Then radii normalised to
`--radius-input` 6, `--radius-row` 10, `--radius-card` 14, `--radius-pill`, with
the old names aliased to the nearest new one. The app is fully re-skinned at the
end of this phase and gets walked end to end in both themes before Phase 2.

**Phase 2 — app bar.** The 🤖 emoji and the gradient-clipped transparent-fill
title both go, replaced by an inline SVG of the two-card mark — back card
`#2A2340` rotated −9° at 12% offset, front card accent-500, eyes at 16% diameter,
corner radius 32% of the tile — and a plain Space Grotesk wordmark with `Deck` in
the accent. The mark becomes the favicon, which the emoji could not be. The header
stops being `brand … margin-left:auto … actions` and becomes a three-part grid:
brand and search on the left, spacer, controls on the right, search capped at
520px, keeping its `/` chip and its results dropdown. The moon button becomes a
segmented two-state switch with explicit Dark and Light options and 40px hit
targets; `applyTheme` stamps `data-theme-switching` on `<html>` for one frame and
a global rule zeroes every transition while it is present, which is how "0ms, no
cross-fade, no flash" is enforced without stripping transitions the rest of the
time. Finally the page header gains a progress bar tinted with the topic's
category hue, and `makeStat` loses its ❓ 📂 💻.

**Phase 3 — sidebar.** The fourteen-emoji `topicIcons` map
(`js/navigation.js:8–14`) becomes a `categoryMarks` map of `{ monogram, hue }`,
plus the same for the eight theory tracks and the glossary. Tiles render as
`<span aria-hidden="true">`, since the label beside them already carries the
accessible name. Sub-items gain `9/12` counts from the progress store in
tabular-nums, while the group count keeps following the tier filter — the sidebar
goes on answering "how much is left to revise", not "how much exists". 📖 Glossary
and the 📄 fallback become tiles, and theory track headings pick up their track
hue on the heading and the bar, per "hue = track, not decoration".

**Phase 4 — question row.** The largest phase, and the one carrying the most
behaviour change.

- *One signal.* Delete `border-left: 3px solid` and its three tier overrides
  (`css/components.css:424–429`). `.question-importance` stops being coloured text
  and becomes a pill: 5/11 padding, full radius, tier fill, 6px rank dot, 11/600
  label at .04em. The `tier-filtered` / `show-*` rules are untouched, so filtering
  still costs no re-render. The same chip goes on search-result badges, so one row
  means one thing everywhere.
- *The checkbox.* A real `<input type="checkbox">` in the row header — styled, not
  replaced — with a label naming the question. Three states: unchecked, checked,
  and done-and-recessed, where the row drops to muted and loses its hover lift, so
  a completed row visibly recedes instead of looking identical to an unread one.
  Click and keypress are stopped from reaching the header's expand handler; Enter
  and Space still expand when focus is on the header itself. Writes fire a small
  event the sidebar and header bar listen for, so all three counters move together
  without a re-render.
- *The measure.* Answer copy at 15/1.7 capped to 72ch. Row numbers padded and
  tabular — `01`, not `1`. A `code` marker on rows whose question carries
  snippets, so a code-bearing question says so before you open it.
- *The code block.* Header keeps its collapse behaviour and gains a filename in
  mono and a copy action; copy uses `navigator.clipboard` with a hidden-textarea
  fallback, because the clipboard API is unavailable on `file://` in some browsers
  and this app is meant to open from disk. Line numbers render as a separate
  `aria-hidden` gutter of N elements — *not* by splitting the highlighter's output
  on newlines, which would corrupt any multi-line comment or raw string. N comes
  from counting newlines in the raw source before highlighting.
- *The action bar.* *Mark as known* mirrors the checkbox. *Review later* writes the
  second set and shows as `reviewed 2d ago` on the collapsed row. *Open in Theory*
  resolves through a reverse index built once from `relatedQuestions` across all
  50 modules, and is omitted entirely for questions no chapter references rather
  than rendered disabled.

**Phase 5 — filter bar and topic chips.** Each tier pill gains the same 6px rank
dot its chip carries, so filter and badge share one visual language; "All" stays
dotless, counts move to tabular-nums, and the disabled-but-present treatment for
empty tiers is kept — a tier with nothing in it still teaches the reader
something. Then `renderKeyTopics` (`js/app.js:118`) slices to six and appends a
`+N more` button revealing the rest in place. `kotlin`'s 37 chips is the case that
motivates it. The expander is a real button with `aria-expanded`, and its state is
not persisted: the summary should be a summary on every arrival.

**Phase 6 — theory module cards.** Read state moves from modules to chapters,
which is the one place this plan exceeds what the handoff describes — see §6, F1.
A new `droiddeck:theory:chapters` set is written with a one-time migration
expanding every already-read module into all of its chapter ids, so nobody loses
progress; a module counts as read when all its chapters are, and the existing
*Mark as read* control keeps working by checking or clearing the whole set. Cards
then lead with `3 of 5 chapters` and a hue-tinted bar, with `30 min` dropping to
secondary and the 📄 ⏱️ going; the primary action reads *Continue* on a
partially-read module and *Start* on an untouched one. Light gets its own module
card tier palette rather than dark reds on white, and the remaining `DOC_KIND`
emoji become inline SVG or plain mono labels.

**Phase 7 — light theme and the missing states.** `.bg-canvas` drops to `.03` in
light and keeps `.6` in dark, done in CSS rather than in the Three.js material so
it holds when the CDN script fails and the canvas stays blank. The button set is
completed — primary, hover, secondary, ghost, focus ring, disabled — in both
themes, with `0 0 0 3px rgba(139,92,246,.2)` on `:focus-visible` across every
element this pass has touched. An empty state covers the case the tier filter can
already produce and currently renders as a blank page. Skeletons replace the
invisible-then-revealed cards in `setupLazyLoading`, the only place the app has a
loading moment worth showing. And glossary terms gain a dashed accent underline
with a popover on hover and focus, dismissed on Escape — matched by a post-render
walk over *text nodes* in theory chapter prose, skipping `code`, `pre`, `a` and
headings. Deliberately not done by rewriting stored answer HTML: the corpus is
validated against an allowed tag subset, and a runtime DOM pass leaves both the
authored content and the validators untouched.

**Phase 8 — close it out.** Delete the alias layer. A grep for `#[0-9a-f]{3,6}`
outside `css/themes.css` must come back empty, and so must a grep for the emoji
ranges across `js/` and `index.html`. Whatever survives is fixed here or the phase
does not close. Then record the pass: `docs/ARCHITECTURE.md` gains a paragraph on
the two-layer token model, `docs/verification-log.md` gains the dark/light parity
walk, and this plan is marked built.

## 6. Decisions and findings

**F1 — the one place this exceeds a restyle.** Section 07 item 8 asks module cards
to read "X of Y chapters". The app tracks read state per *module*
(`js/theory.js:51`), so the number the design system asks for does not exist yet.
Phase 6 adds chapter-level state with a migration. The alternative — showing
"3 of 12 modules" on a track and leaving cards binary — is smaller but does not
match the specimen, and a card reading `0 of 5` when you have read four chapters
is worse than the bare count it replaces.

**D1 — fourteen question topics, nine sanctioned hues.** Section 05 defines ten
marks, drawn from the *theory* tracks. The question sidebar has fourteen topics,
and the rule "never introduce a hue outside this set" means five must share.
Sharing by kinship rather than by exhaustion — a topic takes the hue of the theory
track its content maps onto — keeps the hue meaningful:

| Tile | Topic | Qs | Hue, and why |
| --- | --- | --- | --- |
| Co | Kotlin Coroutines | 20 | sky — its own track |
| Fl | Kotlin Flow API | 17 | teal — its own track |
| Kt | Kotlin | 66 | violet — Language Foundations |
| An | Android | 135 | lime — The Android Platform |
| Lb | Android Libraries | 28 | amber — Data & work *(shared)* |
| Ar | Android Architecture | 8 | indigo — Architecture & Design |
| Dp | Design Pattern | 15 | indigo — `design-patterns` sits in that track *(shared)* |
| Sd | Android System Design | 28 | fuchsia — `system-design` is in Synthesis |
| Ut | Android Unit Testing | 10 | rose — Testing & perf |
| Tt | Android Tools & Tech | 30 | rose — `build-and-tooling` is in that track *(shared)* |
| Jc | Jetpack Compose | 33 | pink — Building UI |
| Jv | Java | 48 | violet — Language Foundations *(shared)* |
| Ds | Data Structures & Algorithms | 10 | fuchsia — `algorithms` is in Synthesis *(shared)* |
| Ot | Other Topics | 17 | slate — the neutral, as Glossary is |

Every hue is one of the nine. Five are shared, and each sharing pair is genuinely
adjacent in subject — the monogram, not the hue, is what disambiguates.

**D2 — what "reviewed 2d ago" measures.** The specimen shows a collapsed row
reading `reviewed 2d ago`. This plan reads that as the timestamp of the last
*Review later* action, so the store keeps a date per flagged question rather than
a bare set. The alternative — time since the row was last expanded — is cheaper
but records browsing rather than studying, and theory's own read-state comment
already argues that opening a page is not reading it. Cheap to change; it is one
field.

**D3 — the Theory link when the corpus has none.** Roughly a third of questions
are referenced by no chapter. The button is omitted for those rather than shown
disabled, on the grounds that a control which is never enabled teaches nothing.
Worth flagging because the specimen shows all three actions together, and this
makes the row's action bar variable-width.

**D4 — the CDN scripts.** Three.js and GSAP are untouched by this pass. They are
already optional and already fail gracefully, and the constellation survives at 3%
in light. Noted only because §07 item 5 is the one place the design system talks
about the backdrop at all, and a reader might expect it removed rather than dimmed.

## 7. Risks

**Line numbers corrupt highlighted code.** Real, and the reason the gutter is
rendered separately. Splitting highlighter output on `\n` breaks multi-line
comments and raw strings, which `code-highlight.js` matches in one alternation by
design. 272 snippets carry output panes; a sample spanning Kotlin, Java and XML
gets read after the change.

**The checkbox swallows the expand gesture.** The row header is a `role="button"`
with a keydown handler. The checkbox stops propagation on both click and keydown;
Enter and Space on the header itself still expand.

**Progress lost on the storage migration.** The chapter store is written *before*
the module store stops being read, and the module store is left in place for one
release rather than deleted.

**IBM Plex Sans reflows dense layouts.** It is wider than Inter at equal size.
Sidebar labels, tier filter pills and module card titles are the three places to
check — done in Phase 0, rather than discovered in Phase 5.

**Emoji hide in files the grep misses.** The first sweep found emoji in
`navigation.js`, `theory.js` and `index.html`; a second, wider pass found more in
`app.js` — `makeStat`, reference links — outside the original character class.
Phase 8 greps the Unicode ranges, not a hand-written list.

**A hard-coded hex survives the alias layer.** That is what the alias layer is
for: an unconverted colour is visibly wrong next to converted neighbours long
before the closing grep runs.

**Contrast regressions in light.** Accent 600 on white is the known one and is in
the token map. Every commit that touches a component is walked in both themes
before it lands — the handoff's parity rule, kept per commit rather than per phase.

## 8. Verification

This pass touches no corpus file, so the validators should be unchanged
throughout, which makes them a useful regression gate rather than a formality.
Both run before every commit:

```bash
node tools/validate-theory.js
node tools/validate-questions.js
```

`tools/check-doc-links.js` hits the network and runs per phase, not per commit, as
`CLAUDE.md` requires. Beyond the validators, each commit is checked by hand:

- **Both themes, every commit.** Not at the end of a phase — the handoff asks for
  parity, and parity checked late is parity re-done.
- **Keyboard.** `/` focuses search; Enter and Space expand a row; every
  interactive element shows the 3px ring on `:focus-visible`; Escape dismisses the
  glossary popover.
- **Touch.** Checkbox, theme switch, filter pills and the `+N more` expander all
  clear 40px.
- **Type floor.** Nothing below 13px anywhere, including the mono counts.
- **From disk.** Opened as `file://` as well as served — the clipboard fallback
  and the localStorage tolerance both matter there, and "opening the file from
  disk works" is a stated property of this codebase.
- **Widest and narrowest.** The app bar change is motivated by wide displays; the
  sidebar drawer is where narrow breaks.

## 9. Where this plan turned out to be wrong

**The constellation could not wait for Phase 7.** Light theme was rendering with
a dark sidebar and a dark app bar, because both are translucent and the canvas
sat behind them at 60% opacity. That is not a cosmetic defect — it made light
look half-applied, which would have made "verify both themes on every commit"
useless for the five phases between Phase 1 and the one scheduled to fix it. The
one-line cap moved into Phase 1.

**Two alignment bugs came out of the line-number gutter, and neither was the one
§7 predicted.** The risk register worried about tearing the highlighter's markup,
which the separate-gutter design avoided exactly as intended. What actually broke
was the strut: an inline `<code>` cannot shrink a line box below its block's
line-height, so the code rendered at the `<pre>`'s inherited 24.75px while
computing as 21.25px; and a `<pre>` left in generic `monospace` does not measure
like one set in JetBrains Mono. Both metrics became tokens the two elements read
in common.

**A `<label>` around its own checkbox toggles it twice.** The label re-forwards
the click to the control it labels, so a direct click landed back where it
started and the row never recorded anything. It is a `<span>` with `aria-label`
now.

**A substring match on `tier-` matches `tier-filter-option`.** The "All" pill
quietly grew a rank dot of its own. The three tiers are named one by one.

**The glossary popover measured itself while `display: none`.** A hidden element
reports a zero rect, so it always concluded it fitted and always ran off the
right edge. It measures the term against its own max-width instead.

**The alias layer was the right call, and deleting it was not free.** Phase 1's
two-layer split did what it was for: the app was correctly re-skinned in one
reviewable commit, and no hard-coded colour survived unnoticed. But 378 call
sites still referenced the old names by Phase 8, so the deletion was a mechanical
sweep rather than the incremental shrinking the plan imagined. Worth doing, worth
knowing it lands in one commit rather than seven. The regex that removed the
alias blocks also took the semantic tokens sitting inside them — shadows, syntax
colours, diagram parts — which a token cross-check caught immediately. That check
(every `var(--x)` used, against every `--x:` defined) is cheap and belongs in
`tools/` if this ever happens again.

**Two design decisions the corpus settled, not the specimen.** Roughly a third of
questions are referenced by no theory chapter, so *Open in Theory* is omitted for
those rather than shown disabled — D3 as written. And glossary terms are marked
once per page rather than once per element: "main thread" appears in seven
consecutive paragraphs of the threading module, and underlining all seven teaches
nothing the first one did not.
